Tested in the code

The repository has automated tests that run the same checks in Python and JavaScript, including 11 "attack" memos written to fool the checker (a rounded number hiding a failure, the right number with the wrong meaning, a memo recommending approval for a loan outside policy). Why the AI runs in the browser

Borrower files hold bank statements and tax data. The model downloads once and runs on this device through WebGPU, so no file leaves the laptop and no API key is needed. Code, not the model, decides every result, so a small model is enough.

Needs a browser with WebGPU (recent Chrome or Edge on a desktop). Everything else works in any browser.

About this project

The problem

AI can draft a credit memo in minutes, but a lender's reviewer still asks two things: does this loan break our own policy, and can I trust the numbers? General AI models are known to make confident mistakes with figures from financial documents, so reviewers end up re-checking everything.

Who it's for

Credit reviewers deciding one loan file at a time, and credit-policy heads deciding what the rules should be.

Key product decisions

  • Code decides, AI only rewords. Every pass or fail comes from code, so the same file always gets the same answer and every result traces to a document page.
  • Problems first. Reviewers see failures and missing documents before anything that passes.
  • The AI never types a number. Code writes the outline with placeholders, the model rewords it, and code fills the figures back in, then checks figures, meaning and the outcome.
  • Overrides need a reason. Approving a broken rule is recorded only with a written reason, in a saved audit log.
  • On-device AI. Borrower data never leaves the laptop; no API key or server.

What I learned by testing

I tried to break my own checker and found 5 ways, including a rounded number hiding a failure and the right number with the wrong meaning. That led to the placeholder design. A 0.5B model also ignored the memo format when asked to write from raw facts, which is why the AI now only rewords a code-written outline.

Honest limits

  • All 12 borrowers and the policy are made up and simplified (for example, DSCR uses EBITDA).
  • It starts from clean, structured data. Reading figures from real PDFs, the hardest part, is not built.
  • The meaning check uses word lists, so unusual phrasing can slip past it.
  • No real users have tested it yet.

Next steps

Talk to five credit analysts; read figures from real documents with a confidence score; add a deviation-approval matrix (which rule break needs which approver).

Built with

Plain HTML, CSS and JavaScript (one file, hosted on GitHub Pages), WebLLM + WebGPU for the on-device model, and a Python version of the same rule engine with automated tests.
